# 失败轨迹分析网页要求

## 一个实验一个入口

按模型、checkpoint 和 benchmark 区分实验。仓库首页和 README 提供相同的实验名称、权重、统计及可直接访问的分析页链接。不同权重单列。新实验使用独立的 experiments/<实验名>/ 目录，已有独立发布页可直接链接。

## 页面内容与阅读顺序

1. **实验概况**。列出权重来源、评测范围、场景设置、任务数、每任务轨迹数、总数、成功数、失败数及成功率。写明哪些批次通过验收，以及是否覆盖完整评测范围。
2. **分类图谱**。按可见行为统计一级主标签，注明分母、已判读数、待判读数及独立诊断数。图中展示实际有样本的类别。区分原始成功率和失败样本内部占比。
3. **分类明细**。表格列为「一级大类（合计）」「二级分类及具体表现」「轨迹数」「轨迹编号」。较长的编号列表可展开，每个编号都能打开该条详情。
4. **代表案例**。每个有样本的一级类别优先选 2–3 条可区分的表现，样本少时按实展示。提供可播放视频、任务、编号、二级标签、关键时刻或时间顺序，以及支持判定的画面描述。
5. **全量轨迹**。覆盖本实验全部正式失败。列表与详情均单列一级、二级标签及代码，和前面的分类表共用同一套映射。支持按编号、任务、场景或两级标签检索、分页和导出。详情关联原始 ID、场景种子、任务指令、步数、观测证据、原片和顺序关键帧。多机位录像标明视角。
6. **判定依据和独立诊断**。完整展示「一级主标签」「二级分类」「判定依据与边界」表。X 区列出运行、评测、索引或录像异常的依据、编号、数量、处理方式及尚未审计的范围。

## 逐条标注

- 读取验收批次的正式 episode 记录，保留原始成功标志、任务、种子和视频映射。逐条对照录像与真实任务指令。给每条正式失败分配稳定的实验内编号，保留其原始编号。
- 每条有一个主标签，可有多个次标签。主标签取片尾仍未恢复的关键表现。已恢复的动作写入事件链。确有可见因果关系时优先记录上游事件，并记录后果。
- 沿用 RoboTwin 的 A 抓取／起运、B 持物／搬运、C 放置／插入／释放、D 推动／机构／工具、E 干扰／环境扰动、F 任务目标／流程、G 交互停滞、H 终态待核及 X 独立诊断。跨 benchmark 时依据真实任务调整二级判据，明确写出差异。完整的 23 个二级分类及边界见[本次分类定义](../experiments/qwenoft-robotwin-140k/taxonomy.json)。
- 明确掉落、错配等事件优先于之后的停滞。看见操作持续停住且机制未明时用 G；确实缺少判断精度、遮挡关系或机构终态的证据时用 H。尚未看过的录像标为待判读。
- 单独记录协作方式、重复动作、结束方式、原因假设、置信度和恢复实验验证状态。达到步数上限仅说明轨迹如何结束。
- 说明每条的审阅深度、采样时点或区间。对短暂滑脱、接触受阻、按钮行程等边界案例回看连续帧；证据仍不足时保留不确定性。各实验的分布来自本实验录像。

## 发布验收

- 核对总数等于成功数加失败数。各二级计数与一级小计一致，行为分类、独立诊断和待判读合计等于全量失败数。
- 逐条核对分类表、全量列表、详情和导出的轨迹 ID 与两级标签。检查重复或缺失编号、失效媒体及公开页面中的本机路径。
- 从发布首页打开实验，测试类别筛选、编号跳转、视频播放、关键帧和下载。GitHub Pages 项目站使用相对资源路径，新增实验后保留已有入口。
